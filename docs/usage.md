## 仓库与快捷键

仓库管理仅收录本机已有仓库，不提供远端仓库浏览或克隆入口；已打开仓库仍支持 fetch/pull/push。旧版本的最近仓库记录自动保留，仓库组及本地列表持久化存储。移除列表记录不会删除磁盘文件。列表中的分支和变更数来自最近一次读取，可在本地仓库界面刷新；无法读取的仓库保留在列表中并标明状态。

扫描支持普通仓库和 Git 链接工作树，不跟随子目录符号链接，跳过隐藏目录、`node_modules` 和 `vendor`，最多扫描 12 层、20,000 个目录或 2,000 个仓库，并支持取消。达到上限或遇到无法读取的目录时会提示。扫描本身只读取，只有勾选并添加后才保存到本地列表；加入列表不会自动打开仓库。

从其他窗口切回时，仅在后台检查当前仓库，不进入全局忙碌状态。未变化的列表和预览保持原样；外部文件修改更新相关状态及正在查看的内容，分支、标签等引用变化才重读已加载的历史范围，保留选择与滚动位置。仓库列表不自动逐个刷新，仍可用工具栏或 `⌘R` 手动刷新。弹窗、读取、写操作或未保存的冲突编辑期间跳过自动检查。

| 快捷键 | 操作 |
| --- | --- |
| ⌘O | 添加仓库 |
| ⌘⇧O | 扫描文件夹 |
| ⌘⇧L | 本地仓库 |
| ⌘R | 刷新 |
| ⌘Enter | 提交 |

界面使用 MyGo Native UI。Diff 默认根据差异面板的可用宽度自动选择统一／并排布局，也可在布局菜单中手动选择；手动选择和旧版本的布局偏好会保留。支持行内变化和语法高亮、长行换行与两侧同步垂直滚动；侧栏和文件面板分隔线可拖动调整。布局、面板尺寸、文件排序和各仓库的提交说明会在正常关闭时保存，重新打开后恢复。二进制、纯重命名、权限变更及截断差异使用原始文本预览。

单文件右上角的“差异／全文”切换在原面板中只读查看完整内容，支持选择、复制和文件内查找（点击“查找”或聚焦正文后按 `⌘F`）。未暂存文件比较暂存区与工作区，已暂存文件比较 HEAD 与暂存区，历史文件比较第一父提交与该提交；全文的版本菜单沿用这两端，删除文件默认展示删除前的版本。切换差异、全文及版本会保留各自的阅读和查找状态，切换文件或读取到变化后的内容时更新。

完整文本每侧最大 1 MiB，二进制、符号链接、子模块及特殊文件不提供全文正文，也不会将截断内容当成完整文件。可读取完整两端时，Diff 可以展开补丁之外的未修改内容，并沿用 Git 原始区块；外部修改造成全文与补丁不一致时保留 Git 区块并提示刷新，刷新前暂停区块与逐行操作。整份贮藏差异不提供单文件全文切换。

文件列表分为上方的“已暂存文件”和下方的“未暂存文件”，各自独立滚动，空分区自动收紧。搜索框下方分别提供状态筛选、排序和视图菜单：

- 默认显示全部变更，可筛选冲突、未跟踪或已跟踪变更，并与路径搜索组合使用。筛选后各分区显示匹配数与总数，批量暂存和取消暂存仅作用于匹配文件；隐藏的勾选项保留选择，但不参与当前批量操作。切换仓库会清空临时筛选。
- 支持按路径、文件名或文件状态排序，以及倒序。同名或同状态的文件按完整路径排序；状态按所在暂存分区判断。排序方式和视图偏好在正常关闭后保留，旧版本的文件名排序偏好继续生效。
- 平面列表连续显示仓库相对路径，长路径可横向滚动查看；目录树按文件夹分层，目录优先，文件在所属目录内排序，支持折叠和方向键导航。悬停文件可查看完整路径，切换视图保留当前文件、Diff 和勾选状态。折叠目录只影响展示，不改变批量操作范围。

窗口顶部左侧显示仓库名称、当前分支与领先／落后数量，右侧集中放置获取、拉取、推送、分支、合并和仓库设置；最右侧齿轮打开应用设置。文件筛选与 Diff 操作保留在各自内容区域。

顶部工具栏“更多”菜单提供“贮藏更改…”入口。侧栏支持方向键导航，窄窗口中放不下的工具栏操作会收进末尾的溢出菜单。

## AI 提交说明

暂存需要提交的文件后，点击提交说明旁的“AI 生成”。默认使用本机 Magpie，优先从 `MAGPIE_ADDR` 或 `~/.config/magpie/gateway.json` 发现地址。应用设置的 AI 页分为“连接与模型”和“生成偏好”，适用于所有仓库。点击“连接”加载模型；默认优先选择可用的 `group/codex`，否则选择模型列表中的首项。连接失败可重试，没有模型时需先在 Magpie 中配置。原有手动本机地址仍使用 Magpie 协议；其凭证继续从启动环境的 `MAGPIE_API_KEY` 读取。

连接方式选择“自定义服务”后，可使用 OpenAI Responses、OpenAI Chat Completions 或 Claude Messages 协议。填写服务的 Base URL（例如 `https://api.openai.com/v1` 或 `https://api.anthropic.com/v1`），输入 API 密钥后点击“保存密钥”，再连接并选择模型；服务不提供模型列表时，可直接填写模型 ID。远程服务必须使用 HTTPS，本机服务允许 HTTP；免密的本机服务可留空密钥。

API 密钥保存在 macOS 钥匙串中，按协议与服务地址分别管理，不写入普通设置文件。“清除密钥”只删除当前协议和地址对应的记录；输入新密钥后点击“取消”保留原有记录。更换协议或地址不会将原密钥发送给新服务；切回“自动发现本机 Magpie”继续使用原有自动连接方式。

尚未同意 AI 发送且未选择模型时，点击“AI 生成”会先打开应用设置的 AI 页。测试连接并选择模型后，关闭设置，再次点击“AI 生成”；配置过程不会发送暂存差异，也不会自动开始生成。已使用过 AI 的用户仍可沿用自动选择模型。

生成只发送全部已暂存文件的路径和文本差异，不受文件筛选或勾选影响，不读取未暂存内容。首次生成前会提示数据发送范围；Magpie 连接的模型可能在云端运行。自定义服务会显示实际发送地址，更换协议或地址后需要重新确认。点击“开始生成”并成功保存后，授权会全局记住，跨仓库和重启不再重复提示；取消或保存失败则下次仍需确认。二进制文件只提供变更摘要；超过 96 KiB 的差异会提示拆分提交或手动填写，避免静默截断。

默认生成中文 Conventional Commit，例如 `feat(ai): 添加提交说明生成`。空草稿直接填入结果，已有草稿先显示建议，点击“采用建议”后替换；“撤销生成”恢复采用前的草稿，后续手动编辑受到保护。生成期间可取消，也能继续浏览差异或手动提交；暂存区变化、切换仓库或关闭窗口会使旧结果失效。AI 不会自动暂存、提交或推送。

生成按钮旁的菜单提供“AI 设置…”入口；连接或模型异常时也可直接“前往设置”。暂存差异超过 96 KiB 时，仅暂停 AI 生成，点击“手动填写”即可继续编写并提交。暂存内容未变化时不重复生成；调整暂存内容后恢复入口，在其他工具中调整后可切回窗口或手动刷新。

应用设置可修改默认语言与格式；仓库设置的 AI 页可单独覆盖这两项，默认跟随应用。这些偏好仅保存在 51Code 的本地设置中，不修改 Git 配置。

## 暂存与丢弃

已暂存和未暂存文件分区之间的分隔线可上下拖动，聚焦后也可用方向键调整；手动调整的比例会保留到下次打开应用。两个文件列表分别滚动，首次使用时仍会按文件数量收紧较短的分区。

区块操作只支持完整预览的普通已跟踪文本修改；新增、删除、重命名、二进制、模式变更和截断预览使用整文件操作。支持跨区块勾选，逐行替换的删除行和新增行可独立选择；若选择会拼接无末尾换行的内容，会要求同时选择对应增删行。

区块应用只修改索引，保留工作区；Git 在索引锁内严格核对目标文件的旧 blob，拒绝把过期区块偏移应用到其他位置。HEAD、其他文件及工作区仍可能在版本核对后被外部修改，版本核对不是跨进程事务。

丢弃仅影响工作区，恢复为暂存区版本；支持不超过 4 MiB 的普通文件，包括恢复删除、二进制文件和删除未跟踪文件。冲突、符号链接、目录、子模块和 intent-to-add 文件需用对应工具处理。

操作前将恢复副本保存在应用数据目录的 `discard-backups` 中，不自动清理，可从工具栏“更多”菜单中的“打开恢复副本文件夹”打开：

- `metadata.json` 记录仓库、路径、时间和原权限；原本已删除的文件以 `present: false` 记录。
- `content` 保存原始字节，恢复时将其复制回原路径，并按元数据恢复权限。

副本写入失败或确认后文件、索引、HEAD 变化会中止操作；执行前再次核对，但不与外部编辑器形成跨进程事务。

## 历史、分支与远程

侧栏“版本比较”支持输入完整或短提交 ID、分支、标签及 `HEAD~1` 等提交表达式，输入框会补全本地／远程分支及标签的完整引用。选择“两端快照”查看基准与目标提交的直接差异；选择“共同祖先”查看两者共同祖先到目标提交的改动，适合审阅分支自身的变化。没有共同祖先或存在多个共同祖先时会提示改用快照比较。

点击“⇄”交换方向并重新比较。文件列表、Diff、全文与查找沿用现有阅读组件，比较结果不提供暂存或丢弃操作。结果固定为本次解析出的提交，并显示实际比较起点和目标；引用移动或刷新仓库后保留已加载结果，再次点击“比较”才重新解析引用。读取可取消，失败保留此前结果与输入。

提交记录和本地分支的右键菜单支持从该对象新建分支或本地标签；标签右键支持从标签对应的提交新建分支，包括附注标签。表单显示固定的创建起点，输入名称后检查本地同类名称及路径冲突，创建前再次校验，不覆盖已有引用。右键创建分支默认不切换，勾选“创建后切换到新分支”后才切换；顶部“分支”入口保留默认创建并切换的习惯。若分支已创建但切换失败，表单保留结果并提供“重试切换”，不会重复创建。创建操作不会自动推送。

仓库侧栏的“工作区”分组依次放置文件变更、提交历史、搜索、版本比较、贮藏和工作树入口，下方排列分支、标签和远端，返回仓库入口固定在底部。分支、标签和远端分类均可折叠；标签分类和各远端默认收起，避免大量引用挤占常用入口。当前分支使用圆点和加粗名称标记，蓝色行表示当前选中的引用或目录。

本地分支、远程分支和标签按 `/` 分层显示，例如 `a/b/c` 显示为 `a → b → c`，目录带文件夹图标，可点击名称或箭头折叠、展开。路径目录默认展开，在本次应用会话中，刷新、折叠父分类或目录、切换仓库后保留折叠状态；不同仓库、引用类型和远端的状态互不影响。树支持方向键导航、左右键折叠展开和回车选择，悬停可查看完整引用。

默认分支及其所在目录优先排列，其他引用保留原有排序。本地默认分支优先采用 `origin/HEAD`，其次采用各远程 HEAD 一致指向的分支；缺少明确结果时优先显示本地 `main`，再选 `master`。各远程内部按自身 HEAD 置顶默认分支，不额外联网查询。

远程分支先按远端分组，再按分支路径分层。点击具体分支打开检出窗口，检出、切换、重命名和删除操作始终使用完整引用。`HEAD` 是远端默认分支引用，仅作展示。带 `/` 的远端名称仍作为一个完整远端显示。

历史顶部可选择“所有分支／当前分支”和“显示远程分支／隐藏远程分支”，默认显示所有分支及远程分支。“当前分支”只显示从当前 HEAD 可达的提交，包含已合并历史，游离 HEAD 时仍可使用。隐藏远程分支会排除仅由远程引用可达的提交，并隐藏远程引用标签；本地分支、标签或当前 HEAD 仍可达的提交保留，不影响侧栏远端树。筛选在本次会话中保留，滚动续载及刷新沿用该范围；切换筛选重新从首屏加载，取消或失败保留原结果和范围。

工作区侧栏的“搜索”独立于“提交历史”，首次进入不自动查询，按回车或点击搜索执行。支持全部内容、提交信息、提交 ID（完整或短 SHA）、分支、文件变更和用户：全部内容匹配提交正文、作者、邮箱与 ID；分支按名称匹配本地及远程分支，返回这些分支可达的提交；文件变更匹配新增或删除行的内容；用户匹配作者或邮箱。搜索按字面值、不区分大小写，可叠加仓库相对文件路径与日期范围，日期按本地时区的作者日期计算，包含起止当天。路径保留首尾空格，不追踪重命名前的旧路径。

搜索与历史分别保留条件、结果、选择和列表滚动位置；“文件历史”会进入搜索并带入路径。“在提交历史中查看”定位搜索结果，若历史筛选排除了该提交，则切换为全部历史。修改条件后需要重新执行；滚动续载及刷新沿用上次执行的条件。首次读取 100 条，向下滚动接近已加载内容的底部时自动续载最多 500 条，不再显示“加载更多”按钮。续载保留当前提交、Diff 和阅读位置；到达末尾后停止，失败或取消后可点击“重试”继续。搜索最长 30 秒，单条提交记录最大 4 MiB；超时或取消保留此前结果及输入。提交差异中，首提交比较空树，合并提交比较第一父提交。

本地有修改时，最新历史顶部显示“未提交更改”及文件数量，包含已暂存、未暂存和未跟踪文件。点击后在历史页查看分组文件和差异，通过“前往文件变更”继续暂存与提交。空心节点只连接当前 HEAD；当前 HEAD 不在列表中时不画连线。搜索页和较早历史页不显示该行。刷新保留正在查看的提交或工作区文件；工作区清空后，该行消失，若正在查看它则转为当前 HEAD 的详情。

单击标签会在历史中定位对应提交并展示文件差异，支持轻量标签和附注标签，不改变当前分支。目标超出已加载历史时读取目标所在页，可继续加载更早记录或返回最新提交；目标被当前筛选排除时保留筛选与提交详情，点击“在全部历史中查看”后才清除筛选并定位。标签右键菜单提供复制标签名、查看标签提交、从此标签新建分支和删除标签。

新建标签只创建本地轻量标签，创建目标为选中提交或当前 HEAD。普通分支删除遵循 Git 的合并检查：有上游时检查上游，否则检查 HEAD；强制删除另行确认，当前分支或被 worktree 使用的分支不能删除。检出远程分支时创建本地跟踪分支，已有唯一跟踪分支时直接切换。

远程操作使用现有 Git/SSH 凭证，不会自动填写或交互式请求密码。Pull 只允许快进，出现分叉时可先获取，再合并对应远程分支。只有一个远程且已有上游时直接推送；多个远程时先选择目标远程及分支，默认选中当前上游，向其他远程推送不会改变已有上游。无上游时先发布分支，成功后自动设置上游。仅推送明确选定的分支，不强推或附带标签。

远程设置只编辑单个获取地址，保留现有独立推送地址及其他配置；多地址配置需使用命令行修改。发布窗口展示 Git 地址重写后的实际推送地址，拒绝镜像远程和多个推送目标。发布前核对当前分支、提交及远程配置，编辑或移除远程前核对配置；外部变化会要求重新确认，这些核对不构成跨进程事务。分支发布使用明确的本地引用，远程已有不同历史时交由 Git 拒绝非快进推送。

## 贮藏与冲突

贮藏支持查看 Diff、创建（可包含未跟踪文件）、应用、应用并移除及确认删除。应用贮藏发生冲突时保留贮藏记录，解决后由用户决定是否删除。

冲突编辑支持最大 1 MiB 的 UTF-8 文本，可预览基础、当前与传入版本，编辑合并结果并暂存。二进制、大文件及符号链接可以选择完整版本或删除。子模块冲突需要外部 Git 工具处理。

冲突保存会核对读取时的文件与索引版本，防止覆盖已经发生的外部编辑；普通暂存不会直接将冲突标记为解决。应用可识别 merge/rebase/cherry-pick/revert，提供继续、中止或跳过操作，但尚不支持发起交互式 rebase。

Git 操作仍会使用仓库配置的 hooks 和提交签名，应用内继续操作不会打开终端编辑器。打开仓库应与直接在该仓库运行 Git 一样，信任其配置与 hooks。

## 工作树（Worktree）

“工作区”分组中的“工作树”显示同一 Git 仓库的主工作树及链接工作树，包括分支、提交、目录，以及锁定、失效、未提交内容和忽略文件状态。选择后可打开对应工作目录；仓库的分支、暂存区和冲突状态始终来自实际打开的工作目录。切换仓库不会复用其他仓库的工作树列表。

“新建工作树…”可从指定提交创建新本地分支，或使用未被其他工作树占用的现有本地分支。目标目录不能覆盖已有内容，也不能位于另一个工作树内部；不会强制检出或重置已有分支。

选择另一个工作树，在“更多”菜单中选择“合并到当前工作树…”，确认来源与目标提交后合并。合并前要求两端无未提交内容且没有进行中的 Git 操作，目标需位于本地分支；冲突会保留合并状态，通过原有文件变更与继续／中止操作处理。

“移除工作树…”只允许移除已合并到当前目标 HEAD 的干净链接工作目录，保留本地分支。主工作树、当前工作树、锁定或失效目录不能移除；未跟踪文件、忽略文件、未提交内容和进行中的 Git 操作都会阻止移除。合并和移除前会再次核对目录归属、提交及状态，变化后需要重新确认；不会强制移除或自动清理其他工作树。

## 应用与仓库设置

“通用 → 侧栏”可分别显示或隐藏搜索、版本比较、贮藏和工作树入口，默认全部显示。四项独立保存，对所有仓库生效；文件变更和提交历史始终保留。关闭当前页面的入口会返回文件变更，菜单、快捷键及其他操作入口仍可使用，已有贮藏记录和工作树目录不会被删除。

点击窗口右上角齿轮，或按 `⌘,` 打开应用设置，通过顶部标签切换“通用 / Git / 快捷键 / 更新 / AI”。标题栏使用 Apple SF Symbols 关闭图标。通用页可选择跟随系统、浅色或深色外观，以及界面语言。外观、语言、快捷键以及自动检查和自动下载开关即时生效；检查频率自动保存，下次启动应用后生效。Git 页的默认提交姓名与邮箱需要点击“保存”，会写入全局 Git 配置并影响其他 Git 工具。

界面语言可选自动检测、简体中文、繁體中文或 English，选择后由 MyGo 保存，下次启动继续使用；自动检测跟随系统首选语言，未匹配到支持语言时使用简体中文。界面语言与 AI 提交说明的输出语言独立。

打开仓库后，通过工具栏或“仓库”菜单进入“仓库设置”，查看提交身份和管理远程地址。提交身份默认沿用 Git 的配置解析结果，也可勾选“为此仓库单独设置”，填写并保存仓库专属身份。取消勾选并保存会移除仓库配置中的直接身份覆盖，继续继承已有配置，不会复制全局值或修改 include、条件 include 与工作树配置。linked worktree 共用仓库级配置，工作树专属配置仍优先；“当前生效”展示实际配置值及其来源。

设置面板通过标题栏右侧的关闭按钮、`Esc` 或点击面板外关闭。身份编辑在点击“保存”前不会修改 Git 配置；点击“取消”放弃输入，其他关闭方式会在存在未保存的身份修改时要求确认。外部修改导致配置过期时会阻止覆盖，需要重新打开设置。远程编辑或移除完成后返回原来的设置页面。

右下角显示版本号，点击检查更新，悬停查看当前版本与构建信息。发现可用更新时显示“新版本 v…”，点击打开原生更新窗口；选择稍后提醒仍保留提示，跳过该版本后清除提示。通过 `51Code → 关于 51Code` 查看完整版本信息。

## 应用更新

在原生 `51Code` 菜单中选择“检查更新…”，或在设置中点击“立即检查更新”。开启自动检查时，正式构建在启动约 10 秒后检查，此后按设置的频率检查。支持每小时、每 6 小时、每天和每周，默认为每天；修改后下次启动应用生效。关闭自动检查时频率选择禁用，仍可手动检查更新。默认只检查并提示，由用户选择安装、稍后提醒或跳过版本。用户可在设置或更新窗口选择以后自动下载，下载完成后仍由用户决定何时重启。下载失败、取消或签名不匹配不会安装更新。

更新通过 HTTPS 从自有对象存储下载，并由 MyGo 验签安装，更新窗口同样使用原生界面。不需要 GitHub CLI、GitHub 登录或存储凭证。开发模式不执行更新；将正式应用从 DMG 拖入有写权限的 `/Applications` 或 `~/Applications` 后使用。普通窗口关闭、退出和更新重启都会检查正在执行的操作，保存提交说明，并询问是否丢弃未保存的冲突编辑；取消后可以继续工作。界面偏好与提交草稿保存在应用数据目录的 `native-state.json`。

安装过更新功能引入前版本的用户，需要手动安装一次包含更新功能的版本。尚未上传首个版本时，应用检查更新会报清单不存在。更新包的 Ed25519 签名不能替代 macOS 的代码签名与公证。
